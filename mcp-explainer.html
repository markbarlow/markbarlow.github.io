Ravelin's view ends hereIt saw two tool calls. It cannot see, trace or recall where this data goes next.

The server is Ravelin's. What it hands over is Acme's to protect.

Ravelin controls

  • Authenticating callers & scoping access to Acme's data only
  • Which tools exist and what each can return
  • Logging and rate-limiting the calls it receives

Acme is responsible for

  • Who in Acme can connect, and with which permissions
  • Everything that happens once the data is in the chat: copies, shares, other agents & MCPs
  • Storage, retention, DPIA & legal basis for the PII now in its own systems

Treat an MCP connection like giving a person an export button: grant least privilege, minimise PII in tool outputs, and log what leaves.
